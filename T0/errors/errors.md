# errors

## 函数功能对比

| 函数 | 核心作用 | 使用场景 | 关键特点 |
| :--- | :--- | :--- | :--- |
| **`New(text)`** | **创建错误** | 生成一个带文本信息的新错误对象 | 最常见，但每次调用都会返回一个独立的新对象，不适合做错误判断的基准 |
| **`Is(err, target)`** | **判断相等** | 判断错误链中是否包含某个特定的“哨兵错误” | 解决 `err == target` 在包装后失效的问题，可以穿透多层包装 |
| **`As(err, target)`** | **类型断言** | 将错误链中的某个错误转换为指定的具体类型 | 用于从包装后的错误中提取出底层的具体错误类型（如 `*os.PathError`） |
| **`Unwrap(err)`** | **解包一层** | 获取被包装的下一层错误 | 只解一层，且仅支持单错误包装（`Unwrap() error`）；不支持多错误包装类型 |
| **`Join(errs)`** | **合并错误** | 将多个错误合并成一个错误 | 收集一批错误同时返回，`Is` 和 `As` 能自动遍历合并后的错误树 |
| **`AsType(err)`** | **泛型提取** | 提取特定类型的错误（属于语法糖） | 通常是基于 `As` 封装而成的泛型辅助函数，用于简化类型断言代码 |

## 关键点

1. **`Is` 和 `As` 是“检测工具”**：`Is` 通常用来判断是否是某类错误（如 `os.ErrNotExist`），而 `As` 用来获取错误中包含的具体信息（如文件名、状态码）。两者都会自动遍历错误链（包括 `Join` 产生的多错误树），因此能穿透层层包装。
2. **`Unwrap` 是“手动解包”**：它与 `Is`/`As` 不同，只负责解开当前错误的一层包装，需要手动循环调用才能遍历整个链，且对包含多个错误的 `Unwrap() []error` 返回 `nil`。
3. **`New` 与 `Is` 的关系**：使用 `Is` 时，通常要用 `New` 创建一个包级变量作为 `target`（哨兵错误），这样才能在错误链中进行比较判断。

简单来说：**`New` 用于创建错误，`Is` 判断错误类型，`As` 提取错误细节，`Unwrap` 是底层的解包实现，而 `Join` 用于把多个错误打包在一起。**
